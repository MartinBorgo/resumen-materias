### Sucesión de Fibonacci
La sucesión de Fibonacci es el mejor ejemplo de donde se puede aplicar la programación dinámica, el algoritmo clásico utilizando recursión lo que hace que se produzcan muchas llamadas en cascada repercutiendo así en el rendimiento del algoritmo.
El problema puede ser resuelto de forma iterativa, utilizando un arreglo para almacenar los resultados intermedios tal y como se puede observar a continuación
```python
def fibonacci(n: int) -> int:
    t = [0] * (n + 1)
    t[0] = 1
    t[1] = 1
    
    for i in range(2, n + 1):
        t[i] = t[i - 1] + t[i - 2]
    
    return t[n]
```

Optando por esta alternativa el tiempo de ejecución del algoritmo se reduce notablemente a un orden $\Theta(n)$.
### Coeficientes Binomiales
Consideremos ahora el cálculo de coeficientes binomiales, el cual posee la siguiente fórmula:
$$
\binom{n}{k} =
\begin{cases}
1 & \text{Si $k = 0$ o $k=n$} \\
\binom{n-1}{k-1} + \binom{n-1}{k} & \text{Si $0 < k < n$} \\
0 & \text{En caso contrario}
\end{cases}
$$
Al solucionar este problema utilizando dividir y conquistar de forma recursiva se generarán muchas subinstancias donde se repiten cálculos, se puede evitar esto utilizando programación dinámica utilizando un ***triángulo de pascal*** para calcular el resultado de forma eficiente, tal y como se expone a continuación:
```python
def coeficiente_binomial(n: int, k: int) -> int:
    # Optimización: usar sólo el vector actual
    c = [0] * (k + 1)
    c[0] = 1
    
    for i in range(1, n + 1):
        # Actualizamos de derecha a izquierda
        # para no sobrescribir valores necesarios
        for j in range(min(i, k), 0, -1):
            c[j] = c[j] + c[j - 1]
    
    return c[k]
```

Esta versión tiene una complejidad temporal de $\Theta(nk)$, mientras que su complejidad espacial corresponde al orden $\Theta(k)$.
### Probabilidad de Ganar una Serie de Juegos
Supongamos que estamos ante una situación en la que existe un juego donde participa $A$ y $B$, donde se quiere calcular la probabilidad de que uno de los dos jugadores gane una serie de juegos, en donde:
- Ambos jugadores deben obtener $n$ victorias para ganar.
- Existe una probabilidad constante $p$ de que $A$ gane un partido.
- Existe una probabilidad constante $q = 1  - p$ de que $B$ gane un partido.

Se puede implementar una solución a este problema utilizando recurrencias, pero pueden existir subinstancias del problema que se calculen múltiples veces, por lo que se puede reformular el problema ligeramente aplicando programación dinámica, quedándonos el siguiente algoritmo:
```python
def probabilidad_ganar(n: int, p: float) -> float:
    prob = [[0 for _ in range(n + 1)] for _ in range(n + 1)]
    q = 1 - p
    
    for s in range(1, n + 1):
        prob[0][s] = 1
        prob[s][0] = 0
	
    for s in range(1, n + 1):
        for k in range(1, s):
            prob[k][s - k] = p * prob[k - 1][s - k] + q * prob[k][s - k - 1]
	
    for s in range(1, n + 1):
        for k in range(0, n - s + 1):
            prob[s + k][n - k] = p * prob[s + k - 1][n - k] + q * prob[s + k][n - k - 1]
    
    return prob[n][n]
```

El tiempo de ejecución y el espacio adicional requerido pertenece al orden $\Theta(n^2)$, aunque este último puede ser optimizado para que pertenezca la orden $\Theta(n)$.
### Problema del Cambio
Como vimos en la unidad anterior, se puede resolver el problema del cambio utilizando un algoritmo *greedy*, no obstante este tipo de algoritmos no arrojan un resultado óptimo para todos los sistemas monetarios.
Este problema se puede resolver utilizando programación dinámica, creando una tabla $c[i, j]$ en donde:
- $i$ representa cada denominación disponible.
- $j$ representa el monto a pagar, que va desde 0 hasta $N$, siendo $N$ el monto del que se quiere conseguir el cambio.
- $c[i, j]$ es la cantidad mínima de monedas de denominación $i$ necesarias para pagar cada monto $j$.

Adicionalmente, se cuenta con un arreglo $d[i]$ que contiene las denominaciones de cada moneda del sistema monetario en cuestión. Para reconstruir la solución al problema, se parte de $c[n, N]$ y se recorre la tabla hacia atrás, basándose en los siguientes criterios:
- Si $c[i,j] = c[i-1, j]$ entonces dicha denominación no debe formar parte de la solución óptima.
- Si $c[i,j] \neq c[i-1, j]$ entonces dicha denominación debe formar parte de la solución óptima.

Con todo esto en mente, entonces el algoritmo queda conformado de la siguiente manera:
```python
def cambio_optimo(N: float, denom: list[float]) -> list[float]:
    n = len(denom)
    c = [[float('inf') for _ in range(N + 1)] for _ in range(n + 1)]
    
    for i in range(n + 1):
        c[i][0] = 0
    
    for i in range(1, n + 1):
        for j in range(1, N + 1):
            di = denom[i-1]
            
            if i == 1 and j < di:
                c[i][j] = float('inf')
            
            if i == 1 and j >= di:
                c[i][j] = 1 + c[1][j - di]
            
            if i > 1 and j < di:
                c[i][j] = c[i-1][j]
            
            else:
                c[i][j] = min(c[i-1][j], 1 + c[i][j - di])
    
    # Reconstrucción de las monedas usadas
    monedas_usadas = []
    i, j = n, N
    while j > 0:
        if i > 1 and c[i][j] == c[i-1][j]:
            i -= 1
        
        else:
            monedas_usadas.append(denom[i-1])
            j -= denom[i-1]
    
    return monedas_usadas
```

El algoritmo tiene complejidad $\Theta(nN)$ en tiempo y espacio, donde $n$ es el número de denominaciones y $N$ es el monto a pagar. Por otro lado, para reconstruir la solución, se parte de $c[n, N]$ y se recorre la tabla hacia atrás siguiendo las decisiones tomadas, por lo tanto, el tiempo requerido para realizar la reconstrucción es del orden $\Theta(n + N)$.
### Problema de la Mochila
Para el problema de la mochila visto anteriormente tenemos $n$ objetos indivisibles, cada uno con un peso $w_i$ y un valor $v_i$. El problema consiste en que se cuenta con una mochila con capacidad $W$ y lo que se busca en llegar dicha mochila con objetos tal que se maximice el valor que se lleva dentro de la misma sin sobrepasar la capacidad de esta.
Si bien en su momento habíamos visto como un algoritmo greedy puede resolver este problema el mismo deja de ser óptimo cuando no se puede dividir los objetos, por lo que puede recurrirse a la programación dinámica para resolver este problema.
A nivel de implementación el algoritmo es muy similar al expuesto anteriormente, creándose una tabla $V[i, j]$ en donde:
- $i$ representa los objetos que se pueden introducir en la mochila.
- $j$ representa la capacidad de la mochila, dicho valor va desde 0 hasta $W$.
- $V[i, j]$ contiene el mayor valor posible obtenido con esos objetos y esa capacidad.

Para reconstruir la solución al problema, se parte de $V[n, W]$ y se recorre la tabla hacia atrás, basándose en los siguientes criterios:
- Si $V[i, j] = V[i-1, j]$ entonces no se incluye al objeto $i$ como parte de la solución óptima.
- Si $V[i, j] \neq V[i-1, j]$ entonces se incluye al objeto $i$ como parte de la solución óptima.

Teniendo todas estas consideraciones en cuenta, el algoritmo para resolver el problema de la mochila queda conformado de la siguiente manera:
```python
def mochila(pe: list[int], val: list[int], cap: int) -> list[int]:
    n = len(pe)
    vx = [[0 for _ in range(cap + 1)] for _ in range(n + 1)]
    
    for i in range(1, n + 1):
        for j in range(cap + 1):
            if pe[i-1] > j:
                vx[i][j] = vx[i-1][j]
            else:
                vx[i][j] = max(vx[i-1][j], vx[i-1][j-pe[i-1]] + val[i-1])
    
    objetos_seleccionados = []
    i, j = n, cap
    while i > 0 and j > 0:
        if vx[i][j] != vx[i-1][j]:
            objetos_seleccionados.append(i-1)
            j -= pe[i-1]
        i -= 1
    
    return vx[n][cap], objetos_seleccionados
```

La complejidad temporal y espacial de este algoritmo corresponde al orden $\Theta(nW)$, mientras que la composición del resultado pertenece al orden $O(n + W)$.
### Búsqueda del Camino más Corto
En unidades anteriores vimos como el algoritmo de Dijkstra permite encontrar el camino más corto desde un punto de partida hacia el resto de nodos del grafo. El algoritmo de Floyd utiliza programación dinámica para resolver este problema partiendo del hecho de que si un nodo $k$ está en forma parte del camino más corto de $i$ a $j$, entonces los subcaminos de $i$ a $k$ y de $k$ a $j$ también deben ser óptimos.
Con esto en mente, entonces podemos crear una matriz $D$ que contenga el valor del camino desde cualquier punto de partida hacia el resto de nodos del grafo. Adicionalmente, se puede crear una matriz $P$ que contenga en las posiciones $P[i,j]$ el nodo al que se debe ir para llegar al destino, de esta manera:
- Si $P[i,j] = 0$ se posee un arco directo hacia el nodo destino.
- Si $P[i,j] \neq 0$ en dicha posición se encontrará por el que se tiene que pasar para llegar al destino de forma óptima.

El algoritmo nos quedaría de la siguiente manera:
```python
def floyd(L: list[list[int]]) -> tuple[list[list[int]]]:
    n = len(L)
    D = [[L[i][j] for j in range(n)] for i in range(n)]
    P = [[0 for _ in range(n)] for _ in range(n)]
	
    for k in range(n):
        for i in range(n):
            for j in range(n):
                if D[i][k] + D[k][j] < D[i][j]:
                    D[i][j] = D[i][k] + D[k][j]
                    P[i][j] = k + 1
	
    return D, P
```

La complejidad temporal corresponde al orden $\Theta(n^3)$, si bien tiene el mismo orden que el algoritmo de Dijkstra, el algoritmo de Floyd es más simple de implementar, con la ventaja de que los compiladores pueden aplicar optimizaciones a los bucles `for`, por lo que en términos generales suele tener un mejor rendimiento, aun así se recomienda usar el algoritmo de Floyd en grafos densos mientras que para grafos ralos es más recomendable utilizar Dijkstra.
### Subsecuencia Común de Máxima Longitud (LCS)
Supongamos que tenemos una cadena de caracteres, una subsecuencia de la misma se obtiene al eliminar 0 o más caracteres de esta. Una ***subsecuencia común*** es una subsecuencia que aparece en dos cadenas dadas.
El problema de LCS consiste en encontrar la subsecuencia común más larga entre dos cadenas dadas, este problema resulta útil al momento de realizar comparaciones entre secuencias de ADN o para detectar similitudes entre archivos, texto o códigos fuentes.
Este problema se puede resolver de forma eficiente utilizando programación dinámica, construyendo una tabla $L[i,j]$, en donde:
- $i$ representa a cada uno de los caracteres que componen la cadena $A$.
- $j$ representa a cada uno de los caracteres que componen la cadena $B$.
- $L[i,j]$ representa la longitud de la LCS de los primeros $i$ caracteres de $A$ y los primeros $j$ caracteres de $B$.

Dicha matriz se va rellenando siguiendo los siguientes criterios:
$$
L[i, j] =
\begin{cases}
0 & \text{Si $i = 0$ o $j=0$} \\
L[i-1,j-1] + 1 & \text{Si $A[i-1] = B[j-1]$} \\
max(L[i-1,j], L[i,j-1]) & \text{Si $A[i-1] \neq B[j-1]$}
\end{cases}
$$
Traduciéndolo a una implementación particular en un lenguaje de programación nos quedaría de la siguiente manera:
```python
def lcs(A: str, B: str) -> list[list[int]]:
    m, n = len(A), len(B)
    
    L = [[0] * (n + 1) for _ in range(m + 1)]
    
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if A[i - 1] == B[j - 1]:
                L[i][j] = L[i - 1][j - 1] + 1
            
            else:
                L[i][j] = max(L[i - 1][j], L[i][j - 1])
	
    return L, L[m][n]
```

La complejidad temporal y espacial de dicho algoritmo pertenece al orden $\Theta(mn)$ en donde $m$ y $n$ son las longitudes de las cadenas $A$ y $B$ respectivamente.
### Multiplicación de Matrices en Cadena
Dado un producto entre matrices $M = M_1M_2 \cdots M_n$ el problema consiste en encontrar el orden óptimo de multiplicar las matrices de forma tal que se minimicen la cantidad total de multiplicaciones escalares.
Aunque la multiplicación de matrices es asociativa, el orden en que estas se multipliquen puede afectar drásticamente la eficiencia. Múltiples ejemplos muestra diferencias de hasta 19 veces en el número de multiplicaciones necesarias según el orden en el que se realizan las multiplicaciones.
Este problema se puede resolver empleado programación dinámica utilizando una matriz $m[i,j]$ que almacene el número mínimo de multiplicaciones que se necesitan para multiplicar las matrices $M_i$ y $M_j$ respectivamente. Adicionalmente, se cuenta con una matriz $k[i,j]$ para rastrear el mejor punto de corte en donde dividir la multiplicación.
>[!note] Representación de las Dimensiones de las Matrices
>Este algoritmo utiliza una arreglo $d$ para representar las dimensiones de las matrices involucradas en la multiplicación, de esta forma la matriz $M_i$ es una matriz de $d_{i-1} \times d_i$.

La implementación del algoritmo nos quedaría de la siguiente manera:
```python
def matriz_multiplicacion_cadena(dim: list[int]) -> list[list[int]]:
    n = len(dim) - 1
    m = [[0] * n for _ in range(n)]
    k_opt = [[0] * n for _ in range(n)]
	
    for s in range(1, n):
        for i in range(n - s):
            j = i + s
            m[i][j] = float('inf')
            for k in range(i, j):
                costo = (
                    m[i][k]
                    + m[k + 1][j]
                    + dim[i] * dim[k + 1] * dim[j + 1]
                )
                if costo < m[i][j]:
                    m[i][j] = costo
                    k_opt[i][j] = k
	
    return m, k_opt
```

Como se puede apreciar la complejidad temporal del algoritmo pertenece al orden $\Theta(n^3)$, mientras que su complejidad espacial al orden $\Theta(n^2)$.
### Problema del Viajante
El problema de viajante consiste en dado un conjunto de ciudades se quiere encontrar un recorrido que pase exactamente una vez por cada ciudad recorriendo la menor cantidad posible de kilómetros y que al finalizar el viaje nos encontremos nuevamente en el punto de partida.
Este problema puede ser representado mediante un grafo $G=\langle N, A \rangle$ en donde $N = \{1,2,3, \dots, n\}$ es el conjunto de nodos y $A$ es el conjunto de arcos. Sea $G[i, j]$ la distancia del nodo $i$ al $j$, la cual es infinita si no existe un arco directo entre ambos nodos.
El problema satisface el principio de optimalidad, lo que permite resolverlo mediante programación dinámica. Consideremos que siempre se parte del nodo 1, en tal caso sea $S \subseteq N - \{1\}$ e $i \in N$ tal que $i \notin S$ entonces $D(i, S)$ es la distancia mínima desde $i$ hasta 1 pasando exactamente por todos los nodos de $S$ tal que:
$$
\begin{align}
& D(i, \emptyset) = G[i, 1] \\
& D(i, \{j\}) = G[i, j] + D(j, \emptyset) \\
& D(i, S) = \min_{j \in S} \left\{ G[i, j] + D(j, S \setminus \{j\}) \right\}
\end{align}
$$
Esto da pie a la siguiente implementación:
```python
def tsp(G: list[list[int]]) -> tuple[int]:
    from functools import lru_cache
	
    n = len(G)
	
    @lru_cache(maxsize=None)
    def D(i, S):
        if not S:
            return G[i][0]
        return min(G[i][j] + D(j, tuple(k for k in S if k != j)) for j in S)

    nodos = tuple(i for i in range(1, n))
    return D(0, nodos)
```

La complejidad temporal de este algoritmo pertenece al orden $\Theta(n^2 \cdot 2^{n-1})$, mientras que su complejidad espacial pertenece al orden $\Theta(n^2 \cdot 2^n)$. Si bien el rendimiento no es muy bueno, en términos general es mucho mejor que el resto de algoritmos los cuales poseen un orden factorial.
