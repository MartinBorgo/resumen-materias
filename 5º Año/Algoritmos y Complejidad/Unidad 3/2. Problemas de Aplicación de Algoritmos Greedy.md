## Árbol de Cubrimiento Minimal
Sea $G = \langle N,A \rangle$ un grafo no dirigido y conexo, donde $N$ es el conjunto de nodos y $A$ es el conjunto de arcos. Cada arco tiene una longitud no negativa. El problema consiste en encontrar un subconjunto $T$ de los arcos de $G$ tal que todos los nodos permanezcan conectados cuando se usen los arcos de $T$, y además la suma de las longitudes de los arcos en $T$ sea tan pequeña como sea posible.
Dado que $G$ es conexo, se puede probar que existe una al menos una solución $G' = \langle N, T \rangle$ y que además dicha solución es un árbol. Por lo que $G'$ es el árbol de cubrimiento minimal de $G$.
Podemos abordar este problema de tal manera que se ajuste a las características de un problema que puede ser resuelto mediante un algoritmo greedy. En este caso, el algoritmo de Kruskal y Prim resuelven este problema de forma correcta.
### Algoritmo de Kruskal
El algoritmo de Kruskal resuelve el problema de encontrar un árbol de cubrimiento minimal. Se caracteriza por tener una función de selección que en cada iteración elige el menor de los arcos todavía no considerados. Si el arco seleccionado, junto con la solución parcial, es viable, entonces el arco se incluye en la solución parcial. En caso contrario se descarta.
Inicialmente, el conjunto $T$ de arcos está vacío y mediante cada iteración se van agregando arcos a $T$. Cuando todavía no se llegó a la solución, el grafo parcial formado por los nodos de $G$ y los arcos de $T$ consiste en varios componentes conexos.
Para construir componentes conexos cada vez más grandes, se examinan los arcos de $G$ de acuerdo a sus longitudes crecientes. Si un arco une dos nodos que están en componentes distintos, lo agregamos a $T$. Como consecuencia de eso, los dos componentes forman ahora un único componente conexo. Si el arco une dos nodos del mismo componente, dicho nodo se rechaza, porque su inclusión provocaría un ciclo dentro del grafo. El algoritmo se detiene cuando queda un único componente conexo. Para ilustrar el proceso consideremos el siguiente grafo conexo.

Los arcos ordenados de forma decreciente de acuerdo a sus longitudes, son los siguientes: {1, 2}, {2, 3}, {4, 5}, {6, 7}, {1, 4}, {2, 5}, {4, 7}, {3, 5}, {2, 4}, {3, 6}, {5, 7} y {5, 6}. El algoritmo funciona de la siguiente manera:

|      Paso      | Arco considerado |  Componentes conexos  |
| :------------: | :--------------: | :-------------------: |
| Inicialización |        -         | {1}{2}{3}{4}{5}{6}{7} |
|       1        |      {1, 2}      | {1, 2}{3}{4}{5}{6}{7} |
|       2        |      {2, 3}      | {1, 2, 3}{4}{5}{6}{7} |
|       3        |      {4, 5}      | {1, 2, 3}{4, 5}{6}{7} |
|       4        |      {6, 7}      | {1, 2, 3}{4, 5}{6, 7} |
|       5        |      {1, 4}      | {1, 2, 3, 4, 5}{6, 7} |
|       6        |      {2, 5}      |    Archo rechazado    |
|       7        |      {4, 7}      | {1, 2, 3, 4, 5, 6, 7} |

Como se puede observar, se utilizan conjuntos disjuntos para controlar si un nuevo arco conecta dos nodos que se encuentran en componentes distintos. Cuando el algoritmo termina, $T$ contiene los siguientes arcos: {1, 2}, {2, 3}, {4, 5}, {6, 7}, {1, 4} y {4, 7}. Este algoritmo tiene un tiempo de $\Theta(a \cdot log \ n)$
### Algoritmo de Prim
El algoritmo anterior selecciona el siguiente arco a comparar sin tener en cuenta la conexión con los arcos precedentes. El algoritmo Prim realiza la selección de forma local, partiendo de un nodo inicial arbitrario, construyendo el árbol de forma ordenada. El algoritmo opera de la siguiente manera:
1. Selecciona un nodo arbitrario por el cual comenzar.
2. Desde el nodo o nodos ya conectados, elige el arco de menor coste que conecte con un nuevo nodo.
3. Agrega el nuevo nodo y el arco al árbol.
4. Se repite el proceso hasta que todos los nodos del grafo estén conectados.

Si bien es más sencillo de entender que el algoritmo de Kruskal, la principal desventaja es que tiene una complejidad temporal de $\Theta(n^2)$.

>[!note] Criterio de Utilización de los Algoritmos
>En estos casos como $n - 1 \leq a \leq n(n-1) /2$ se debe tener en cuenta que si $a \thickapprox n$ conviene utilizar Kruskal, pero si $a \thickapprox n^2$ entonces conviene utilizar Prim.
## Problema de la Mochila
Se tienen $n$ objetos y una mochila. Cada objeto $i$ tiene un peso $w_i$ y un valor $v_i$. La mochila tiene una capacidad máxima de $W$. Se pretende encontrar la manera de cargar la mochila de forma que se maximice el valor de lo transportado y se respete su capacidad máxima.
En esta primera versión del problema asumimos que los objetos pueden ser divididos, o sea que podemos decidir cargar solo una fracción de cada objeto. Entonces, se pretende encontrar valores $x_i /0 \leq xi \leq 1$ de forma tal que se maximice
$$
\sum_{i = 1}^n x_iv_i
$$
Siempre que dicha sumatoria sea menor o igual que $W$. Teniendo esto en cuenta, hay por lo menos tres estrategias de selección posibles.
1. Elegir el objeto restante de mayor valor.
2. Elegir el objeto restante de menor peso.
3. Elegir el de mayor valor por unidad de peso.

Se puede demostrar que las dos primeras estrategias resultan en algoritmos que no son correctos; siendo la tercera estrategia la que nos da siempre una solución correcta.
La implementación del algoritmo es directa. Si los objetos ya están ordenados, entonces el ciclo greedy toma tiempo en el $O(n)$; el tiempo total que incluyen el ordenamiento entonces es del orden $O(n \cdot log \ n)$.
>[!tldr] Utilización de Heaps
>También podría ser válido usar un max heap que contenga el elemento de mayor $v_i/w_i$ en la raíz. En este caso, la creación del heap toma un tiempo $O(n)$, mientras que cada entrada en el ciclo greedy llevaría $O(log \ n)$, ya que cada vez que se elimina la raíz se debe restaurar la propiedad del heap. Aunque esto no afecta el análisis en el peor caso, podría ser más rápido cuando se necesitan únicamente unos pocos objetos para llenar la mochila.
## Camino más Corto con Origen Único
Consideremos un grafo dirigido $G = \langle N,A \rangle$, donde $N$ es el conjunto de nodos de $G$ y $A$ es el conjunto de arcos dirigidos. Cada arco tiene una longitud no negativa. Uno de los nodos está caracterizado como el nodo de origen. El problema es determinar la longitud del camino más corto desde el origen a cada uno de los otros nodos del grafo.
Este problema puede ser resuelto por un algoritmo greedy llamado algoritmo de Dijkstra cuyo comportamiento es muy similar a la [[2. Estrategias de Busqueda#Búsqueda de Costo Uniforme (UCS)|búsqueda de costos uniformes]]. Este algoritmo parte de un nodo origen y selecciona el arco de menor valor hacia el siguiente nodo, así de forma consecutiva hasta llegar al destino.
La complejidad temporal de este algoritmo varía de acuerdo a como se lo implemente, la siguiente tabla resume las implementaciones más comunes de este algoritmo.

| Tipo de implementación  |    Complejidad temporal    |
| :---------------------: | :------------------------: |
| Implementación directa  |          $O(A^2)$          |
| Implementación con heap | $O((N + A) \cdot log \ n)$ |
En la implementación que utiliza heaps se debe eliminar la raíz de este al menos unas $n - 2$ veces y elevar en el heap como máximo $a$ veces lo que nos da un tiempo de $\Theta((a + n) \cdot log \ n)$. Si el grafo es conexo, entonces $a \geq n - 1$ dándonos un tiempo de $\Theta(a \cdot log \ n)$. Por lo tanto, la implementación directa es preferible si el grafo es denso, mientras que si el grafo es ralo, conviene utilizar una implementación con heaps.
## Planificación de Procesos
Se tiene un servidor que tiene $n$ clientes para servir. El tiempo de servicio $t_i$ requerido por cada cliente se conoce previamente. El problema consiste en encontrar una secuencia de atención al cliente que minimice el tiempo medio que un cliente permanece en el sistema.
Debido a que el número de clientes es fijo, esto es lo mismo que minimizar el tiempo total de permanencia en el sistema de todos los clientes. Una manera intuitiva de realizar esta planificación es atendiendo primero a los clientes con menor $t_i$. Se puede probar que este método es correcto para este tipo de problemas.
>[!tldr] Implementación y Complejidad Temporal
>Para implementar un algoritmo greedy que resuelva este problema se debe primero ordenar a los clientes de acuerdo a su tiempo de servicio. Como el cuerpo de ciclo es del orden $\Theta(1)$ y dicho ciclo no se repite más de $n$ veces, el tiempo del algoritmo estará determinado generalmente por el tiempo del ordenamiento, el cual es $\Theta(n \cdot log \ n)$.
## Selección de Actividades
dado un conjunto de $n$ actividades $S = \{S_0, S_1, \dots, S_n\}$ y conociendo la hora de inicio y fin de cada actividad $Ini_i$, $Fin_i$ se define que dos actividades son compatibles si no se superponen en el tiempo.
El problema consiste en encontrar el conjunto de actividades compatibles de mayor cardinalidad. Un algoritmo greedy que resuelve este problema consiste en:
1. Ordenar las actividades por orden de finalización creciente.
2. Elegir la primera actividad.
3. Elegir la primera actividad compatible con la última elegida.
4. Repetir hasta que no queden actividades.

Es evidente que el algoritmo es eficiente, ya que solo requiere el tiempo necesario para el ordenamiento más un tiempo que es del $\Theta(n)$ para el proceso de selección. Además, se demuestra que el algoritmo greedy para el problema de la selección de actividades es óptimo si las actividades se ordenan según un orden creciente de su hora de finalización.
## Problema del Viajante
Se tienen $n$ ciudades y las distancias de un viaje entre cada par de ellas representadas en una matriz. Se quiere partir de una de las ciudades y visitar exactamente una vez cada una de las demás ciudades, regresando al punto de partida al final, y recorriendo la menor distancia posible.
Para este problema en particular se puede demostrar que ninguna estrategia de selección de caminos genera un algoritmo greedy correcto en todos los casos. Es más, para cualquier estrategia existen casos cuya solución es muy mala.
