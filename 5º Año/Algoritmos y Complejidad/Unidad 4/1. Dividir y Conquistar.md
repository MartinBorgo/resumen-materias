***Dividir y conquistar (DyC)*** es una técnica de diseño de algoritmos que consiste en descomponer la instancia a resolver en un número de subinstancias más pequeñas del mismo problema.
Esta técnica resuelve sucesiva e independientemente cada una de estas subinstancias, y luego combina las subsoluciones resueltas para obtener la solución a la instancia original. Generalmente, resulta en un algoritmo más eficiente que el original. Es importante entonces determinar para cada problema:
1. Cuáles son las subinstancias, y cómo se encuentran.
2. Cómo solucionar el problema en las subinstancias.
3. Cómo combinar las soluciones parciales.

Para el segundo punto se puede aplicar nuevamente esta técnica, hasta que se llegue a subinstancias de tamaño suficientemente pequeño para ser resueltas inmediatamente.
## Esquema General
Consideremos un problema cualquiera, y supongamos que `adhoc` es un algoritmo simple capaz de resolver el problema, este algoritmo es eficiente sobre instancias pequeñas, puesto que no lo aplicares a instancias grandes. A este algoritmo lo llamamos ***subalgoritmo básico***. El esquema general para algoritmos dividir y conquistar es el siguiente:
```python
def divide_and_conquer(instance):
	if is_small_enough(instance):
		return adhoc(instance)
	else:
		sub_results = []
		# Divide la instancia en l subinstancias
		sub_instances = divide(instance, l)
		for instance in sub_instances:
			sub_results.append(divide_and_conquer(instance))
		
		result = marge_solutions(sub_results)
		
		return result
```

El número $l$ de subinstancias por lo general es pequeño y totalmente independiente de la instancia particular a resolver. Para que un algoritmo que utiliza dividir y conquistar sea considerado valioso, debe cumplir con tres condiciones:
- Debe hacerse una cuidadosa elección de cuándo usar el subalgoritmo básico en lugar de seguir haciendo llamadas recursivas. Es decir, especificar cuándo una instancia es el suficientemente pequeño como para aplicarle el subalgoritmo básico. Este tamaño se denomina ***umbral***.
- Debe ser posible descomponer una instancia en subinstancias y recombinar las soluciones de manera bastante eficiente.
- En la medida de lo posible, las subinstancias deberían ser del mismo tamaño.

>[!tldr] Determinación del Umbral
>La determinación del tamaño del umbral no afecta el orden del tiempo de ejecución requerido por un algoritmo que utiliza dividir y conquistar, pero sí afecta considerablemente las constantes ocultas.
>La elección de un umbral es complejo, dado que un valor óptimo para dicho umbral no depende únicamente de algoritmo en cuestión, sino también de la implementación en particular. Es más para una implementación en específico no se puede hablar de un valor preciso para el umbral sino de uno aproximadamente óptimo.
## Análisis del Tiempo de Ejecución
Si $g(n)$ es el tiempo requerido por un algoritmo dividir y conquistar en instancias de tamaño $n$, sin contar el tiempo necesario para las llamadas recursivas, entonces el tiempo total $t(n)$ utilizado por dicho algoritmo posee la siguiente forma:
$$
t_{DyC} =
\begin{cases}
f(n) & \text{si $n$ es lo suficientemente pequeño} \\
l \cdot t_{DyC}(n/b) + g(n) & \text{si $n$ es una subinstancia grande}
\end{cases}
$$
Asumiendo que $n$ es una instancia grande, siendo $b$ es una constante, tal que $n/b$ aproxime el tamaño de las subinstancias y que $f(n)$ es el tiempo del subalgoritmo básico. Teniendo esto en cuenta, si consideramos que existe un entero $k$ tal que $g(n) \in \Theta(n^k)$, entonces se puede utilizar el teorema maestro para determinar la complejidad temporal de este tipo de algoritmos, es decir, $t(n)$ puede determinarse de la siguiente manera:
$$
t(n) \in
\begin{cases}
\Theta(n^k) & \text{si $l < b^k$} \\
\Theta(n^k \cdot log \ n) & \text{si $l = b^k$} \\
\Theta(n^{log_b \ l}) & \text{si $l > b^k$}
\end{cases}
$$
